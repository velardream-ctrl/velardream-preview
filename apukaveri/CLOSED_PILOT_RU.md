# Закрытый пилот Apukaveri

Стенд предназначен для вымышленных данных. Подготовлены аккаунты владельца, заказчика и помощника. Роль владельца может участвовать как заказчик или исполнитель. Публичная витрина использует отдельную конфигурацию и адрес.

## Настройка Cloudflare

1. Выбрать отдельный поддомен под управлением владельца. Настроить Cloudflare Access для всего поддомена, ограничив политику конкретными тестировщиками. Получить URL команды и AUD приложения. Если домен ещё не подключён к Cloudflare, сначала согласовать адрес и владельца DNS.
2. Создать отдельную D1 `apukaveri-closed-pilot`. Скопировать `wrangler.pilot.example.jsonc` в `wrangler.pilot.jsonc` и заполнить одинаковый домен в `routes` и `PILOT_HOST`, URL команды, AUD и идентификатор D1. Файл локальной конфигурации исключён из Git.
3. Выполнить `node build-static.mjs --server` и проверить конфигурацию командой `npx wrangler@4 deploy --dry-run -c wrangler.pilot.jsonc`.
4. Для новой базы применить миграции командой `npx wrangler@4 d1 migrations apply apukaveri-closed-pilot --remote -c wrangler.pilot.jsonc`.
5. Запустить `node server/seed-pilot.mjs`. Скрипт создаёт временный каталог с `seed.sql` и `credentials.json`, доступными только пользователю запуска. Применить `seed.sql` на отдельной пустой базе через `npx wrangler@4 d1 execute apukaveri-closed-pilot --remote -c wrangler.pilot.jsonc --file <путь-к-seed.sql>`. Учётные данные передавать через защищённый канал и удалить временные файлы после настройки. Повторное применение к той же базе отклоняется уникальностью email.
6. Развернуть `npx wrangler@4 deploy -c wrangler.pilot.jsonc`. Проверить из приватного окна, что запросы без допуска закрыты. С допуском войти под тестовым владельцем и открыть `/admin`. В двух независимых сессиях проверить заказ от владельца к помощнику и заказ от тестового заказчика к владельцу. Подтвердить результат обеими сторонами, выставить оценку и сверить историю в админке.

Сервер проверяет подпись, издателя, AUD и срок токена Cloudflare Access до маршрутизации. Админка требует ещё и сессии владельца Apukaveri. Самостоятельная регистрация и восстановление закрыты для этого контура. Тестовые коды из локального терминала в облако не выводятся.

Внешние push, email, WhatsApp и платежи потребуют отдельных интеграций и проверки. Облачный запуск требует доступа к Cloudflare и отдельного поддомена. Реальные данные можно включать после отдельной проверки настроек безопасности и процессов удаления.

## Тестовый баланс

Сценарий начинается с пополнения условными евро в кабинете заказчика. Подготовленный набор содержит помощников с вымышленными данными для выгула собак в Китеэ, доставки и компьютерной помощи в Йоэнсуу. После принятия адресной заявки заказчик платит с тестового баланса. По окончании работы стороны подтверждают выполнение. Сумма за вычетом комиссии поступает на тестовый баланс исполнителя, затем заказчик может оставить оценку. Начисление видно в истории открытого кабинета. При отмене до подтверждения списанное возвращается заказчику. Исполнитель может потратить тестовые средства на другой заказ или имитировать вывод. При споре средства остаются заблокированными; сценарий разрешения спора пока не реализован.

Ввод данных карты отсутствует, все движения выполняются в тестовой базе. До утверждения реальной платёжной модели проверить правила электронных денег и возможность работы через лицензированного провайдера. Для первого платного запуска сравнить с оплатой отдельного заказа и выплатой через провайдера.
