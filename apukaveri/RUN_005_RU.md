# RUN-005 · стенд Apukaveri
## Запуск в локальном браузере
Из каталога apukaveri на Node.js 24.22+ выполните `node server/local.mjs`. Откройте http://127.0.0.1:8787/sandbox.html. Устанавливать npm-пакеты для этого не требуется. По умолчанию SQLite живёт до остановки процесса. Для сохранения между запусками задайте APUKAVERI_DB равным абсолютному пути к отдельному тестовому файлу вне репозитория.
1. Зарегистрируйте demo-1@example.invalid с придуманным тестовым паролем длиной от 12 символов. Код из строки TEST MAIL в терминале вставьте в поле «Код», подтвердите и войдите.
2. Создайте заявку. В отдельном профиле браузера зарегистрируйте demo-2@example.invalid, выберите тот же город и услугу, включите приём с 9 до 17 и сохраните анкету. Обновите список и примите заявку. В первом окне нажмите «Обновить».
3. Для проверки панели владельца используйте файловую БД. После подтверждения первого адреса выполните в другом терминале `node server/grant-owner.mjs /путь/к/стенду.sqlite demo-1@example.invalid`, обновите страницу. Проверьте статистику, изменение названий FI/RU/EN и комиссии, перечитайте каталог с другого аккаунта.
4. В account.html сохранён прототип сложного календаря и локального предпросмотра фото. В серверной форме кнопка сохранения устанавливает график 09–17 ежедневно. Через API profile доступны интервалы по дням недели и замены дат, включая пустой массив для выходного. Время заказов в API — UTC в миллисекундах с минутной точностью, максимум 24 часа. Отображаемый интервал проверяется поминутно в Helsinki.
## Проверки
`node --test tests/*.mjs`. Браузер: Python Playwright, Chromium, `python tests/browser.py`. Переменная CHROMIUM задаёт путь к исполняемому файлу. Используются только вымышленные данные.
## Перенос на D1
Для локального эмулятора с Wrangler 4 применить `wrangler d1 migrations apply apukaveri-local-test --local -c wrangler.local.jsonc`, затем `wrangler dev --local -c wrangler.local.jsonc`. Это API, браузерные страницы обслуживает Node-стенд. UUID в конфигурации локальный. Для отдельного облачного preview потребуются доступ владельца к выделенной D1, миграция в неё, защищённая тестовая почта, маршрутизация статики и ограничение доступа к preview. Локальную доставку кодов в консоль в облако не переносить.
## Границы
Каталог БД используется на серверном стенде. Главная витрина и расширенный демо-кабинет сохраняют прежние локальные примеры. Подготовлены manifest, service worker и иконки. Кешируется только оболочка стенда. Подтверждения по настоящей почте, R2, проверка документов, полная админка, визуальный редактор, автоматические уведомления, избранные и очередность рассылки, финансовый реестр, возвраты и выплаты остаются открытыми. Следующая итерация — перенести редактор календаря и анкету на API, подключить изолированное хранение и удаление тестовых фото, добавить журнал и сквозные тесты админки и диспетчерской. Обычные аккаунты не могут выдавать роль владельца.
