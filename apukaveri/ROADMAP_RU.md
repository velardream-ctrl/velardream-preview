## Целевая архитектура
Отдельный Cloudflare Worker + D1, при необходимости R2 для изображений; роли customer/provider/admin с серверной авторизацией; одна учётная запись может быть заказчиком и исполнителем. Профили и несколько услуг на человека, города, языки, цены, доступность. Два сценария: выбор из каталога и заявка с откликами. Заказ: requested → accepted → payment_confirmed → in_progress → completed → payout_pending → paid; отмена, спор, возврат как отдельные переходы. Хранить денежные суммы в центах, фиксировать ставку комиссии при заказе, не доверять браузерному расчёту. Время Europe/Helsinki, хранить UTC; тестировать переходы летнего времени, гонки бронирования и возвраты. Платежи только через подходящий для маркетплейса лицензированный PSP с KYC, не копировать обычную оплату Pakkasukko без адаптации.

## RUN-003 — диспетчерская и расширяемый каталог (26.11.2026)
Прототип: index.html — 13 категорий, дополнительные демо-профили, ссылка dispatch.html. dispatch.html — 3 языка, бесплатные/платные услуги, срочная/плановая/объявление, рассылка всем подходящим/избранным/одному, первый принимает; только локальная симуляция, не серверная конкуренция. 7 логических тестов PASS: eligibility, first claim, reject second, favourites, free, unavailable, listing not claimable. ### Целевая реализация
- Конструктор категорий: translated labels/descriptions/fields, icon, order, enabled, payment modes free/paid/cost-share, risk gate, commission per category. Отдельные предложения и запросы; route, pickup/dropoff, seats, departure, luggage, cost allocation for rides; receipts and approved purchase budget for errands. No public private address.
- PWA: reuse Sanastoyhteisö manifest/service-worker patterns after audit; separate worker scope and cache namespace, install guidance, opt-in Web Push, device subscription per user, redacted notification, deep link, unread badge, server inbox and email fallback; no guarantee of delivery, no sensitive lockscreen content. Server-authorized updates across devices; use event stream or polling, no duplicate notifications, quiet hours and availability filters. No offline acceptance of real orders.
- Dispatch: eligibility by verified role/category, city/radius, service window, availability, payment mode, favourite or named recipient. Server atomic conditional update + transactional overlap constraint/reservation, idempotency key, audit trail, expiry, cancellation, no broadcast of child's address. Childcare gate + customer consent for named candidate before care; no emergency service promise.
- Single account: customer/provider switch; individual, Y-tunnus, invoicing service; strong identity verification and consent; private tax fields with encryption/access control and retention. Admin controls per user and platform owner moderation. Service status and legal classification depend on actual arrangement; no automatic assumption that worker is self-employed.
- Payments: proposed commission 15% on labour only; free 0%; reimbursements separately itemized, no commission on carpool until legal review; marketplace PSP (e.g. Stripe Connect pending suitability), KYC, payout, refunds, webhook idempotency, reconciliation, reports. Cash not a tax exemption; do not use it to conceal income. Classified-only model and transaction model separately evaluated.
- Finnish legal sources: https://www.vero.fi/en/individuals/tax-cards-and-tax-returns/income/earned-income/selling-goods-and-services-on-a-digital-platform/ ; https://www.vero.fi/en/businesses-and-corporations/taxes-and-charges/annual-information-returns/dac7/ ; https://www.vero.fi/en/incomes-register/individuals/households-as-employers/ ; https://www.finlex.fi/fi/lainsaadanto/2017/320 ; https://www.finlex.fi/fi/hallituksen-esitykset/2016/161 ; https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/ .
