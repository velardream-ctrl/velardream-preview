# RUN-220 · Массовый перенос текстов песен Suno → Velar Dream Records

## Зачем

У владельца много песен и текстов в Suno. Цель — не перенос музыки и не генерация, а **экономия времени при массовом добавлении авторских текстов в защищённую Studio**.

## Что подтверждено

1. Suno **официально** поддерживает MCP с авторизацией владельца аккаунта и просмотром собственной библиотеки, также функции анализа песен, включая lyrics timings. Источник: https://help.suno.com/en/articles/14551361
2. Нет подтверждённого публичного документированного метода, который гарантированно экспортирует все исторические полные тексты Suno в нужном формате за один запрос. Прежде чем писать автоматический коннектор, надо посмотреть реальные возможности инструментов авторизованного Suno MCP и результат их вызова. Нельзя выдумывать endpoints или читать cookies из браузера.
3. Условия Suno ограничивают автоматизированный скрейпинг: https://suno.com/terms . Приоритет официальный MCP, разрешённый API или официальный пользовательский экспорт, а не скрытые эндпоинты.
4. В действующем `velar-music-manager`: `studio/studio.js` читает приватные коллекции `vmm_catalog`, `vmm_lyrics`, пишет версии текста в `vmm_lyrics` с полями `title`, `upc`, `catalogRow`, `language`, `version`, `text`, временными метками и аудитом в `vmm_audit`. Редактор запрещает создание второй такой же языковой версии. `studio/lyrics-tools.js` уже умеет `cleanSuno` и просматривать тексты.
5. `studio/import.js` импортирует **другой формат полного резервного пакета**, а не данный промежуточный JSON. Не пытаться загружать `velardream-suno-lyrics-review.json` напрямую как резервную копию.

## Текущая тестовая реализация

- Отдельная ветка `feature/run220-suno-lyrics-batch-import-20261123` репозитория `velardream-ctrl/velardream-preview`, базовая ветка `test/mp3-converter-20261122`.
- `suno-lyrics-import/index.html` — локальная страница для подготовки массового импорта.
- `suno-lyrics-import/prepare.js` — нормализация JSON и сопоставление с каталогом.
- `tests/test-suno-lyrics-import.mjs` — проверки повторов, вариантов песен, незаполненных записей.
- Никаких запросов по сети, токенов, загрузок текстов в GitHub, Firebase или Suno со стороны инструмента.
- UI принимает 1) JSON из разрешённого Suno экспорта, 2) (опционально) локальный JSON со списком каталога `[{title,artist,sourceRow,upc,id}]`, 3) (опционально) JSON существующих текстов для обнаружения дублей.
- Проверяемые входные структуры: JSON-массив либо `{songs:[]}`, `{tracks:[]}`, `{clips:[]}`, `{data:{songs:[]}}`. Текст: `lyrics`, `song_lyrics`, `text`, `metadata.lyrics`, `metadata.prompt`. **Эти поля — адаптер общего формата, а не официально подтверждённая схема Suno MCP.** После первого реального результата проверить/уточнить адаптер.
- Сопоставление по нормализованному названию и, когда доступно, исполнителю; исходный Suno ID становится частью названия версии `Suno · <id>`. Неоднозначные совпадения и незнакомые песни помечаются «Нужна сверка», а не пишутся в базу.
- Выход `velardream-suno-lyrics-review.json` — **ТОЛЬКО отчёт для проверки**. В Firestore **ничего не записывается**.

## Что понадобится от владельца

Подключить официальный Suno MCP к поддерживаемому AI-клиенту, авторизовав свой аккаунт без передачи пароля разработчику. Проверить на 3–5 своих песнях возможность получить как минимум `id`, `title`, текст песни, ссылку на исходник, версию. В идеале пагинацию библиотеки и список всех произведений.

**Нельзя утверждать, что доступ к приватной Suno-библиотеке уже подключён здесь.** Отправлять секретные cookie/API токены в чат/исходники нельзя.

## Полноценная интеграция на основной сайт — следующий отдельный PR

После проверки легального источника данных:
1. В защищённой Studio добавить панель «Импорт текстов из Suno» для авторизованного владельца.
2. Прочитать весь каталог и все существующие версии с пагинацией, а не ограничиться нынешним `.limit(1200)` каталогов и `.limit(500)` текстов.
3. Сформировать preview: совпавшие, неизвестные, неоднозначные, дубли, пустые, варианты; поддержать ручное сопоставление и подтверждение.
4. Оставить исходные тексты без изменений: для новых — только создание; существующие не перезаписывать. Вначале сделать бэкап.
5. Добавить безопасную транзакционную запись пакетами, повторную сверку на сервере, идемпотентность по Suno ID, `vmm_audit`, отчёт, восстановление и отмену до записи.
6. В версии текста сохранять авторский порядок и символы: не очищать в автоматическом режиме метки `[Verse]`, `[Chorus]` и т.д. Редактор `cleanSuno` уже предлагает добровольную очистку.
7. Публиковать только те тексты, на которые есть права; разделить приватное хранение текста в Studio и публичное отображение.

**Production Velardream.com, Firestore, приватная Studio и DNS не изменялись.**
